# 1. AMI(Amazon Machine Image)

[EC2](EC2.md)インスタンスを起動するために必要な情報一式をまとめたテンプレート。同じAMIから何個でも同じ構成のインスタンスを複製できる、いわば「金型」。

## 1.1. 含まれるもの

- **OS**: Amazon Linux, Ubuntu, Windows Serverなど
- **ルートボリュームのスナップショット**: インストール済みソフトウェア、設定ファイル、ミドルウェアなど
- **起動時の権限設定**: どのAWSアカウントがこのAMIでインスタンスを起動できるか
- **ブロックデバイスマッピング**: どのストレージボリュームをアタッチするか

## 1.2. 種類

| 種類 | 説明 |
| --- | --- |
| AWS提供AMI | Amazon Linux 2023, Ubuntu, Windows Serverなど、AWSが公式に用意 |
| Marketplace AMI | サードパーティ提供(WordPress, セキュリティ製品などプリインストール済み) |
| カスタムAMI | 自分で構築・設定したEC2インスタンスから作成する独自イメージ |
| コミュニティAMI | 他ユーザーが公開しているAMI |

## 1.3. カスタムAMIを作る流れ

1. EC2インスタンスを起動し、必要なソフトウェア・設定を入れる
2. そのインスタンスから「イメージの作成」を実行 → AMIが生成される
3. 次回以降、そのAMIから起動すれば同じ環境が即座に再現できる

## 1.4. ユースケース

- **Auto Scaling**: 需要に応じてインスタンスを自動増減させる際のテンプレートとして使う
- **バックアップ/災害対策**: 特定時点の環境をAMIとして保存し、障害時に素早く復元
- **定期起動の高速化**: [EventBridgeのcronでEC2を起動する運用](EventBridge.md#12-スケジュールルールの例-cron起動でec2を立ち上げる)で、事前にセットアップ済みのカスタムAMIから起動すれば都度の構築が不要になる

## 1.5. 料金の注意点

AMI自体の作成・保持は無料だが、裏側のEBSスナップショットにストレージ課金が発生する。不要なAMIは登録解除(deregister)し、関連スナップショットも削除しないと課金が残り続ける。
