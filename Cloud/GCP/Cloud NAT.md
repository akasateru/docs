Google Cloud が提供するマネージドの NAT（Network Address Translation）サービス。プライベート IP のみの VM/GKE ノードを外部公開せずにインターネットへアウトバウンド通信させる。

## 1. 概要

- プライベート IP のみを持つ VM や GKE ノードが、外部から到達可能なパブリック IP を持たずにインターネットへアウトバウンド通信できるようにするサービス
- 逆方向（インターネットからの直接アクセス）は許可しない
- 外部公開せずに済むサーバー（バッチ処理、更新パッチ取得、外部 API 呼び出しなど）に向いている

## 2. 特徴

- **リージョナルサービス:** NAT ゲートウェイは特定の VPC の特定リージョンに紐づく
- **Cloud Router 前提:** 設定には Cloud Router が必須（ルーティング制御に使う器）
- **マネージド/冗長化:** Google 側がインフラを管理し単一障害点なし。NAT インスタンスを自前で運用する必要がない
- **対象範囲を選べる:** サブネット単位、あるいは特定のセカンダリ IP 範囲のみに適用可能
- **ポート割り当て:**
  - 静的: VM ごとに固定ポート数を割り当て
  - 動的: 負荷に応じて自動調整（`enableDynamicPortAllocation`）
- **ロギング:** Cloud NAT のログを Cloud Logging に出力し、接続の成功/失敗を監視可能

## 3. ユースケース

1. プライベート GKE クラスタのノードがコンテナイメージを pull したり外部 API を叩く
2. パブリック IP を持たない Compute Engine VM が OS アップデートを取得
3. セキュリティ要件でインバウンドを一切許可したくないが、アウトバウンドは必要な構成

## 4. 注意点

- NAT できるのはアウトバウンドのみ。インバウンド接続を受けたい場合は Load Balancer や別途パブリック IP が必要（[Cloud VPC](Cloud%20VPC.md) 参照）
- ポート枯渇に注意。同時接続数が多いと NAT ポートが不足しエラーになることがある（`nat_allocation_failed` などのメトリクスで検知）
- 料金は「NAT ゲートウェイの稼働時間」＋「処理データ量」で課金される

## 5. 構成要素（登場人物）

ネットワークを構成する際に登場する主要コンポーネント。

1. **VPC ネットワーク:** すべての土台となるネットワーク（[Cloud VPC](Cloud%20VPC.md) 参照）
2. **サブネット:** リージョンごとのIPレンジ。Cloud NAT はサブネット単位（またはセカンダリレンジ単位）で対象を選べる
3. **VM インスタンス / GKE ノード:** 実際に通信の主体。外部 IP を持たないことが前提（外部 IP があればそちらが優先され NAT は使われない）
4. **Cloud Router:** Cloud NAT 設定の必須の相棒。BGPルーティング用の存在だが、NAT単体利用でも「NATの設定を紐づける器」として必ず作成する
5. **Cloud NAT ゲートウェイ:** Cloud Router に紐づけて作成する、実際の NAT 処理を行うマネージドリソース本体
6. **外部IPアドレス（NAT IP）:** NAT が使う送信元 IP
   - 自動割り当て: Google がプールから自動確保
   - 手動割り当て: 自分で予約した静的 IP を指定（送信元 IP を固定したい時に使う）
7. **ファイアウォールルール:** アウトバウンド通信を許可する egress ルールが必要（デフォルトルールで許可されていることも多い）
8. **ルート:** インターネットへのデフォルトルート（`0.0.0.0/0`）が VPC 側に存在している必要がある
9. **Cloud Logging（オプション）:** NAT のログ出力先。接続の成否をモニタリングする観測者役

### 5.1. 関係イメージ

```
[VM/GKEノード] --(外部IPなし)--> [サブネット]
                                     |
                                  対象範囲
                                     |
                              [Cloud NAT ゲートウェイ] ---紐付け--- [Cloud Router]
                                     |
                              [外部IP(自動/手動)]
                                     |
                                インターネット
```

### 5.2. 構成する順番

1. VPC/サブネットを確認
2. Cloud Router を作成
3. Cloud NAT を作成（対象サブネット・IP割当方式を指定）
4. ファイアウォール/ルートを確認
