# Cloud Spanner

Googleが開発したフルマネージドの分散リレーショナルデータベースサービス。NoSQLの水平スケール性とRDBのACIDトランザクション整合性を両立させた「NewSQL」の代表例。

## 1. 特徴

- **水平スケーラビリティ**: 一般的なRDB（MySQL、PostgreSQLなど）は基本的に単一ノードでの垂直スケールが中心だが、Spannerはノードを増やすことで読み書き性能・ストレージともに線形にスケールする。
- **強整合性 + グローバル分散**: 複数リージョンにレプリカを配置しても外部整合性（external consistency）を保証する。GoogleのTrueTime API（GPSと原子時計を使った高精度時刻同期）によって実現している。
- **SQLインターフェース**: ANSI SQL準拠のクエリが使え、トランザクション（ACID）もサポート。
- **Spanner Vector Search**: ネイティブのベクトル検索機能を持ち、大規模ベクトル検索やメタデータストアとしても利用できる。

## 2. 向いているユースケース

- グローバルにアクセスされる金融系・決済系システムなど、強整合性が必須でかつ将来的に大規模スケールが見込まれるサービス

## 3. トレードオフ

- コストが高め（最小構成でも一定のノード数分の課金が発生する）
- 通常のCloud SQL（Postgres/MySQL互換）で十分なケースでは過剰スペックになりがち
