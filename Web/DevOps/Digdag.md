# 1. Digdag

Treasure Data社が開発したOSSのワークフロー自動化・オーケストレーションツール。YAMLベースの定義ファイルでタスクの依存関係を記述し、データパイプラインやバッチ処理を管理する。Apache Airflowと同カテゴリのツール。

## 1.1. 概要

- 開発元: Treasure Data
- 実装言語: Java/Scala
- ワークフロー定義: YAML形式の `.dig` ファイル（宣言的。Airflowのように定義自体をPythonコードで書くのとは対照的）
- CLIモードとサーバーモードの両方があり、`digdag run` でローカル実行・テストし、`digdag server` でDB管理下の本番運用サーバーとして稼働できる

## 1.2. ワークフロー定義の基本構造

```yaml
+task1:
  sh>: echo "hello"
+task2:
  py>: my_script.main
```

- `+` で始まるブロックが1つのタスク
- タスクをネストさせることで直列・並列実行を制御する（インデントが並列グループを表す）

## 1.3. 主要なオペレーター

| オペレーター | 内容 |
| --- | --- |
| `sh>` | シェルコマンドを実行 |
| `py>` | Pythonスクリプト・関数を実行 |
| `rb>` | Rubyスクリプト・メソッドを実行 |
| `td>` | Treasure Data上でSQLクエリを実行 |
| `_error:` | タスク失敗時のエラーハンドリング処理を定義 |

## 1.4. 主な特徴

- **リトライ設定**: タスク単位でリトライ回数・間隔を指定できる
- **スケジューリング**: cron形式でのスケジュール実行に対応
- **並列・直列制御**: タスクのネスト構造だけで依存関係を表現でき、追加のDAG記法が不要

## 1.5. Apache Airflowとの比較

| 項目 | Digdag | Airflow |
| --- | --- | --- |
| 定義方法 | YAML（宣言的） | Python（コードで記述） |
| 開発元 | Treasure Data | Airbnb → Apache |
| 学習コスト | 比較的低い | Pythonの柔軟性がある分、複雑になりやすい |
| エコシステム | 小規模 | 非常に大きい（プラグイン・Provider豊富） |
