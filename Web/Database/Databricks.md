# Databricks

データレイクとデータウェアハウスを統合した「レイクハウス（Lakehouse）」プラットフォームを提供し、データ基盤とAI/ML基盤を一体で扱える企業向けサービス。

## 1. 概要

- 米サンフランシスコ本社、世界30以上の拠点を持つデータ+AIプラットフォーム企業。
- 分析ワークロード（BI・データエンジニアリング）と運用ワークロード、AI/MLワークロードを単一の基盤上で実行できる点が特徴。
- Snowflakeと並んで「データ+AI基盤」の代表格として比較検討に挙がることが多い。

### 1.1. レイクハウスというコンセプト

従来はデータレイク（大量の生データ保存向け、柔軟だが低信頼・低性能）とデータウェアハウス（構造化データの高速分析向け、高性能だが柔軟性に欠ける）を別システムで運用する必要があった。

- **Lakehouse**はこの2つを1つの基盤に統合し、データレイクの柔軟性・拡張性とウェアハウスの信頼性・パフォーマンスを両立させる。
- 構造化・半構造化・非構造化データを1箇所で扱え、BI・リアルタイム分析・データエンジニアリング・AI/MLワークロードを同一プラットフォーム上で実行できる。
- テーブルフォーマットには**Delta Lake**（自社OSS）や**Apache Iceberg**を利用。

## 2. 主要プロダクト

| プロダクト | 役割 |
| --- | --- |
| Unity Catalog | データガバナンス・アクセス権限管理 |
| Lakeflow | データパイプライン構築（ETL/データエンジニアリング） |
| Lakebase | 運用系（OLTP寄り）データベース機能 |
| Genie / Agent Bricks | 自然言語でのデータ分析・エージェント構築 |
| Lakehouse//RT | Delta Lake/Iceberg上のガバナンスされたデータに対し、別途サービング基盤を構築せずミリ秒単位のリアルタイム分析を実行する機能 |

## 3. Mosaic AI（GenAI開発基盤）

買収したMosaic MLの技術を核に、GenAI開発の一連の流れをプラットフォーム内で完結できるようにした機能群。関連概念は [RAG](RAG.md) を参照。

### 3.1. 構成要素

- **基盤モデル / LLMOps**: 基盤モデルの利用、ファインチューニング、カスタムモデルのサービング。
- **AI Search**（旧Vector Search、2026年6月改称）: ベクトル検索・全文検索・ハイブリッド検索に対応したDatabricksネイティブの検索基盤。RAGの検索部分を担う。
- **PromptOps / AgentOps**: プロンプト管理やエージェントの運用管理。

### 3.2. Model Serving

- サーバーレスの低レイテンシAPIとしてモデルをホスティング（CPU/GPU両対応）。
- 自社データでRAG拡張・ファインチューニングした生成AIモデルをそのまま本番サービングできる。
- ライフサイクル全体（デプロイ〜モニタリング〜ガバナンス）を通じた自動ロギング・監視機能が付属。

### 3.3. MLflowによるトレーシング・評価

- MLflowはエージェントの推論チェーンの各ステップを記録する。
- エージェントが誤った回答をした際、「どの検索ステップが誤ったコンテキストを引いたか」「どのツール呼び出しが失敗したか」「どこで推論がずれたか」を追跡できる。
- Vector Search（AI Search）→ Model Serving → MLflow評価、という一連の流れを1プラットフォーム内で完結できるのがGenAI開発における強み。
