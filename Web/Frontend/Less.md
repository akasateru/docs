# 1. Less

CSSを拡張したメタ言語（CSSプリプロセッサ）。CSSに変数・ネスト・関数・演算などプログラミング的な機能を追加し、最終的に通常のCSSにコンパイル（変換）して使う。

## 1.1. 基本機能

```less
@primary: #3498db;

.button {
  color: @primary;
  padding: 10px + 5px;   // 演算もできる

  &:hover {              // ネスト記法（&は親セレクタを表す）
    color: darken(@primary, 10%);  // 組み込み関数（色を暗くする）
  }
}
```

- `@変数名` : 値を変数化して使い回せる
- ネスト : セレクタを入れ子にでき、CSSの構造をHTMLの階層に合わせて書ける
- 組み込み関数 : `darken()`, `lighten()`, `fade()` など色操作系が豊富
- Mixin（`.mixin() { ... }`） : スタイルの塊を再利用できる（関数のような役割）

## 1.2. なぜ必要か

素のCSSには変数・条件分岐・関数がなく、以下のような弱点がある。

- 同じ色やサイズの値を何度も直書きする必要があり、変更時の修正漏れが起きやすい
- セレクタのネスト構造を書けず、親子関係が見た目に表れにくい
- 繰り返し使うスタイルの塊を再利用する手段がない

Lessはこれらをコンパイル時に解決し、最終出力は通常のCSSになるため、ブラウザ側の対応は不要。

## 1.3. Sass/SCSSとの関係

同種のCSSプリプロセッサに **Sass（SCSS記法）** があり、実務ではSassの方がよく使われる傾向にある。機能はほぼ同等（変数・ネスト・Mixin・関数）だが、以下の違いがある。

| | Less | Sass(SCSS) |
|---|---|---|
| 実行環境 | JavaScript（Node.js）ベース | Dart製コンパイラ（dart-sass）が主流 |
| 変数記号 | `@変数` | `$変数` |
| 代表的な採用例 | Bootstrap（v3以前） | Bootstrap（v4以降）、多くのモダンフレームワーク |

## 1.4. 現在の立ち位置

近年はビルドツール側でCSS変数（`--変数名`、ネイティブのCSS Custom Properties）や `postcss` のプラグインで同等機能を代替するケースも増えており、新規プロジェクトではSassまたはCSS-in-JS系（styled-componentsなど）、あるいは[TailwindCSS](TailwindCSS.md)のようなユーティリティファーストの手法が選ばれることも多い。
