# 1. クラス図・ER図の読み方

どちらも「箱」と「線」で構成を表す設計図。箱＝もの、線＝関係、線の端の記号＝関係の性質や数量、という読み方の骨格は共通している。

## 1.1. クラス図（UML）

オブジェクト指向設計における、クラス同士の関係を表す図。

```text
┌─────────────┐
│   User      │ ← クラス名
├─────────────┤
│ - name: str │ ← 属性（- はprivate, + はpublic, # はprotected）
├─────────────┤
│ + login()   │ ← メソッド
└─────────────┘
```

### 1.1.1. 関係を表す線の種類

| 線 | 意味 | 例 |
|---|---|---|
| 実線 + 中抜き三角矢印 | 継承（is-a） | `Dog` が `Animal` を継承 |
| 実線 + 白ひし形 | 集約（has-a、緩い所有。部分が独立して存在できる） | `Team` と `Player`（チーム解散してもPlayerは残る） |
| 実線 + 黒ひし形 | コンポジション（has-a、強い所有。全体が消えると部分も消える） | `House` と `Room` |
| 実線 + 矢印 | 関連・依存（参照している） | `OrderService` が `User` を利用 |
| 破線 + 中抜き三角矢印 | インターフェース実現 | `Dog` が `Movable` を実装 |

### 1.1.2. 多重度

線の両端に書かれる数字は「相手が何個対応するか」を表す。

- `1` : ちょうど1つ
- `0..1` : 0または1つ
- `0..*` または `*` : 0個以上（任意の個数）
- `1..*` : 1個以上

例: `User "1" ─── "0..*" Order` は「1人のUserが0個以上のOrderを持つ」。

## 1.2. ER図（Entity-Relationship Diagram）

データベースのテーブル同士の関係を表す図。

```text
┌──────────┐         ┌──────────┐
│  User    │ 1     ∞ │  Order   │
│ id (PK)  │─────────│ user_id(FK)│
│ name     │         │ id (PK)  │
└──────────┘         └──────────┘
```

- 箱 ＝ テーブル（エンティティ）、箱の中の行 ＝ カラム（属性）
- `PK`（Primary Key） ＝ 主キー、`FK`（Foreign Key） ＝ 外部キー（他テーブルの主キーを参照）
- 線の両端の記号（鳥の足のような分岐＝「カラス足記法」）がカーディナリティ（多重度）を表す

### 1.2.1. カーディナリティの読み方（カラス足記法）

| 記号 | 意味 |
|---|---|
| `\|` (一本線) | 1（ちょうど1つ） |
| `○` (丸) | 0（存在しなくてもよい） |
| `<` (足) | 多（0個以上、または1個以上） |

組み合わせ例:

- `1対多`: 「1人のUserが複数のOrderを持つ」→ User側に`1`、Order側に足（多）
- `多対多`: 中間テーブル（例: `UserRole`）を介して表現するのが一般的

## 1.3. 2つの図の使い分け

- **クラス図**: アプリケーションのコード上のオブジェクト構造・振る舞い（メソッド）を設計・共有するための図
- **ER図**: データベースの永続化構造（テーブル定義）を設計・共有するための図

同じ「User」でも、クラス図では「メソッドを持つオブジェクト」として、ER図では「カラムを持つテーブル」として描かれる点に注意する。
