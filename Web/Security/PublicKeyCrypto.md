# 1. 公開鍵暗号方式（RSA / Ed25519）

RSAとEd25519（楕円曲線暗号）の違いと、Ed25519の鍵導出の仕組み、および関連する基礎用語をまとめる。

## 1.1. RSA vs Ed25519 比較

| 項目 | RSA (2048bit) | Ed25519 |
| --- | --- | --- |
| 数学的基盤 | 大きな数の素因数分解の困難性 | 楕円曲線（Edwards曲線）上のEdDSA署名 |
| 用途 | 暗号化・署名・鍵交換など汎用 | 署名専用 |
| 公開鍵サイズ | 256バイト程度 | 32バイト |
| 秘密鍵サイズ | 数百バイト~ | 32バイト |
| 署名サイズ | 256バイト | 64バイト |
| 128bit相当の安全性に必要な鍵長 | RSA 3072bit | 256bit鍵 |
| 署名生成方式 | 実装依存（乱数を使うことが多い） | 決定的署名（毎回同じ入力なら同じ署名） |
| 実装の安全性 | パディング方式や乱数品質次第で脆弱になりやすい（例: PKCS#1 v1.5の問題） | サイドチャネル対策が設計に組み込まれ、実装ミスが起きにくい |
| 普及度 | 歴史が長く、TLS証明書など幅広い規格でサポート | SSH鍵、Gitのcommit署名など新しいシステムで採用が進む |

新規に鍵を作る場合、互換性の制約がなければ鍵サイズ・速度・実装安全性の面でEd25519が有利。古いシステムとの互換性が必要な場面（証明書関連など）ではRSAが依然必要になることがある。

## 1.2. Ed25519の鍵導出（RFC 8032）

Ed25519の鍵ペアは以下の手順で導出される。

1. **シード生成**: 32バイト（256bit）のランダム値 `seed` を生成する。これが秘密鍵の"種"。
2. **SHA-512でハッシュ化**: `seed` をSHA-512でハッシュ化し、64バイトを前半32バイト（`h_left`）・後半32バイト（`h_right`）に分割する。
   - `h_left` → 秘密スカラーの生成に使う
   - `h_right` → 署名時のnonce生成に使う
3. **クランピング（clamping）**: `h_left` に対して以下のビット操作を行い、秘密スカラー `a` を作る。
   - 最下位3ビットを0にする（→ コファクター攻撃対策、[[#1.3. コファクターとコファクター攻撃|コファクター攻撃]]を参照）
   - 最上位ビットを0にする
   - 2番目に高いビットを1にする（→ スカラー倍算を常に一定のビット長にし、タイミング攻撃を防ぐ）
4. **公開鍵の導出**: Edwards曲線上のベースポイント `B` に対して `A = a × B`（スカラー倍算）を計算し、エンコードしたものが公開鍵（32バイト）。

```
seed(32B, ランダム)
  → SHA-512
    → 前半32B → clamping → 秘密スカラー a
    → 後半32B → 署名時のnonce生成に使用
  → a × B（楕円曲線上の点） → 公開鍵 A（32B）
```

### 1.2.1. 署名時のnonce導出（決定的署名）

Ed25519は署名のたびに乱数を使わず、決定的にnonceを導出する。

```
r = SHA-512(h_right || message) mod L   # nonce
R = r × B
S = (r + SHA-512(R || A || message) × a) mod L
```

署名は `(R, S)` のペア（64バイト）。同じメッセージ・同じ秘密鍵なら常に同じ署名になるため、乱数生成器の品質に依存しない。

## 1.3. 基礎用語

### 1.3.1. スカラー（scalar）

楕円曲線暗号では「点（point）」と「スカラー（scalar）」を区別する。

- **点**: 曲線上の座標 `(x, y)`。ベースポイント `B` や公開鍵 `A` はこれ。
- **スカラー**: 点に掛け合わせるただの整数。秘密鍵 `a` はこれ。

「スカラー倍算」は `a × B` のように点 `B` を `a` 回自分自身に足し合わせる演算（整数同士の掛け算とは異なる特殊な演算）。線形代数の「ベクトルに対する、大きさだけを持つ数」という用語が転用されている。

### 1.3.2. コファクターとコファクター攻撃

**コファクター（cofactor）** とは、曲線上の全点の数（位数）を、ベースポイントの位数（素数 `L`）で割った倍率のこと。Ed25519の曲線では全体の点の数が `8 × L` であり、この「8」がコファクター。

曲線上には本来使いたい大きな素数位数 `L` の部分群のほかに、位数が8, 4, 2, 1といった小さい部分群の点が混在する。

**攻撃の仕組み**: 攻撃者が小さい部分群に属する点（低位数点）を細工して送りつけると、相手がその点をスカラー倍算した結果が秘密鍵の下位ビット情報に依存する値になり、繰り返し観測されることで秘密鍵情報が漏洩しうる。

**対策**: クランピングで秘密鍵の下位3ビットを強制的に0にする（`a[0] &= 0xF8`）ことで `a` を必ず8の倍数にし、小さい部分群の影響を無効化する。

### 1.3.3. nonce

**nonce = "number used once"** の略。署名生成のたびに使う一度きりの値。

署名の式は `S = r + hash(...) × a` の形をしており、同じ `r`（nonce）を異なる2つのメッセージへの署名で使い回すと、2つの署名式を引き算することで `r` が消え、連立方程式的に**秘密鍵 `a` が計算されてしまう**。

実例として、PS3のコード署名がECDSAでnonceを固定値にしていたために秘密鍵が漏洩した事故がある。

Ed25519は `r = SHA-512(秘密鍵の後半32バイト || message)` という決定的計算でnonceを作ることで、乱数生成器の品質に依存せずこの問題を回避している。
