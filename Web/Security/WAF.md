# 1. WAF（Web Application Firewall）

## 1.1. 概要

WAFはWebアプリケーション層（L7）に対する攻撃を検知・遮断するファイアウォール。ネットワーク層のFWでは防げないSQLインジェクションやXSSなど、HTTPリクエストの中身を見て判断する必要がある攻撃に対応する。

## 1.2. 一般的なFWとの違い

| 項目 | 一般的なFW（L3/L4） | WAF（L7） |
| ---------- | ------------------------------ | ---------------------------------- |
| 監視対象 | IPアドレス・ポート番号 | HTTPリクエストの中身（パラメータ、ヘッダ、Body） |
| 防げる攻撃 | 不正アクセス、ポートスキャンなど | SQLインジェクション、XSS、CSRFなど |

## 1.3. 検知方式

- **シグネチャ型**: 既知の攻撃パターン（正規表現やルール）に一致するリクエストをブロック。誤検知は少ないが未知の攻撃には弱い。
- **異常検知型**: 通常のトラフィックからの逸脱をスコアリングして判定。未知の攻撃にも対応できるが誤検知（False Positive）が増えやすい。

## 1.4. 主なサービス例

- クラウド型: AWS WAF、Cloudflare WAF、Google Cloud Armor
- アプライアンス型: F5, Imperva など

## 1.5. 運用時の注意点

- 導入初期はブロックモードではなく検知（ログのみ）モードで運用し、誤検知でユーザーの正常な操作をブロックしていないか確認してから本番遮断に切り替える。
- ルールセットは定期的に更新し、OWASP Top 10などの最新の脅威に追従する。
- WAFだけに依存せず、アプリケーション側でも入力値検証・エスケープ処理を行う多層防御が基本。

## 1.6. WafCharm（AWS WAF自動運用サービス）

Cybersecurity Cloud社が提供するSaaS。AWS WAF自体はルールセットの箱を提供するだけで、どのルールを・どう組み合わせて・どう調整するかは利用者側の運用負荷になる。WafCharmはそこをAIで肩代わりするサービス。

### 1.6.1. 何を解決するか

- WAFは導入して終わりではなく、**誤検知（False Positive）による正常リクエストの遮断**と**未知の攻撃への追従**という継続的なチューニングが必要（[1.5](#15-運用時の注意点)参照）。これには専門知識と継続的な運用工数がかかる。
- WafCharmはこの「ルール選定・チューニング・継続更新」を自動化し、専任のセキュリティ担当者がいなくても運用できるようにする。

### 1.6.2. 仕組み

1. AWS WAFの操作権限とアクセスログ（ALB / CloudFront / API Gatewayに対応）を連携。
2. AIとグローバルなビッグデータ（世界中で観測された攻撃パターン）を使い、アクセスログを分析してシグネチャ（WAFルール）を自動生成・更新。
3. 攻撃パターンを検知すると自動でAWS WAFのルールを調整。新規の脆弱性が出た場合はセキュリティリサーチャーがシグネチャを作成・適用する体制もある。
4. 誤検知が発生した場合のチューニング支援や、24時間365日の日本語サポートも付帯する。

### 1.6.3. 料金体系

- AWS Marketplace従量課金（WebACL数・リクエスト数ベースの時間課金）
- 月額固定＋従量（リクエスト数の閾値超過分を課金）
の2パターンから選択可能。

### 1.6.4. 位置づけ

AWS WAFそのものの代替ではなく、AWS WAFの**運用レイヤーを自動化する上乗せサービス**という位置づけ。素のAWS WAFやAWS Managed Rulesを自前でチューニングする運用と比較検討する対象になる。
