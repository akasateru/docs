## 1. SSH(Secure Shell)

SSH（Secure Shell）は、暗号化と認証技術を用いてネットワーク経由で遠隔地のコンピュータ（サーバ）を安全に操作・管理するための通信プロトコル

## 2. sshコマンド

### 2.1. 良く使うオプション

| オプション | 用途                             | コマンド例                       |
| ---------- | -------------------------------- | -------------------------------- |
| **-p**     | ポート番号を指定                 | `ssh -p 2222 user@host`          |
| **-i**     | 秘密鍵ファイルを指定             | `ssh -i ~/.ssh/id_rsa user@host` |
| **-l**     | ログインユーザーを指定           | `ssh -l user host`               |
| **-v**     | デバッグモード（接続状況を表示） | `ssh -v user@host`               |
| -T         |

### 2.2. 関連コマンド

- **`ssh-keygen`**: 公開鍵と秘密鍵のペアを作成する。
- **`ssh-copy-id`**: 公開鍵をリモートサーバーに登録する（パスワードなしログイン用）。
- **`scp`**: SSHを使ってファイルを安全に転送する。
- **`sftp`**: 安全なファイル転送プロトコル（FTPの安全版）。

### 2.3. セキュリティと認証

SSHの認証は大きく2種類。

1. **パスワード認証**: アカウントのパスワードを使用。
2. **公開鍵認証**: 鍵ペア（秘密鍵・公開鍵）を使用。セキュリティが高く、自動化に適している。

## 3. ~/.ssh/config

[\~/.ssh/configについて #SSH - Qiita](https://qiita.com/passol78/items/2ad123e39efeb1a5286b)

.ssh/configは、ssh経由でのリモートサーバーの接続する際に利用される設定ファイル

一般的な書き方の問題点は、指定が増えるとコマンドが複雑になる

```bash
# 一般的な接続方法
ssh hoge.example.com

# ユーザー名を指定する場合は以下
ssh ユーザー名@hoge.example.com

# ポート名を指定する場合
ssh ユーザー名@ホスト名 -p ポート番号

# 公開鍵認証の場合
ssh ユーザー名@ホスト名 -i ~/.ssh/鍵の名前

# ポート名及び、公開鍵認証の場合
ssh ユーザー名@ホスト名 -i ~/.ssh/鍵の名前 -p ポート番号
```

.ssh/configでは以下のように書ける

```bash
Host 任意の接続名(hoge)
HostName ホスト名
User ユーザー名
Port ポート番号
IdentityFile 鍵へのPATH(例えば~/.ssh/hoge.key)
```

このように設定を書いておくと`ssh hoge`のように簡単に接続できる

## 4. OpenSSH

**OpenSSH**: SSHプロトコルをオープンソースで実装したソフトウェア群。OpenBSDプロジェクトが開発・保守しており、Linux/macOS/BSD系OSに標準搭載されていることが多い。Telnetやrshなど平文通信の代替として広く使われている。

### 4.1. 構成コマンド

| コマンド | 役割 |
| --- | --- |
| `ssh` | リモートホストへの接続（クライアント） |
| `sshd` | SSHサーバーデーモン |
| `scp` / `sftp` | ファイル転送 |
| `ssh-keygen` | 鍵ペアの生成 |
| `ssh-agent` / `ssh-add` | 秘密鍵の管理 |
| `ssh-copy-id` | 公開鍵をリモートに配布 |

### 4.2. 主な機能

- 公開鍵認証・パスワード認証
- ポートフォワーディング（トンネリング）
- X11フォワーディング
- `~/.ssh/config`によるホストごとの接続設定管理（[3. ~/.ssh/config](#3-sshconfig)参照）

## 5. SSH証明書認証

**SSH証明書（SSH Certificate）**: 通常の公開鍵認証（[2.3. セキュリティと認証](#23-セキュリティと認証)）を拡張し、TLS証明書のように**CA（認証局）が鍵に署名**する方式。サーバー・クライアントは個々の公開鍵ではなく「特定のCAが署名した鍵かどうか」を信頼の基準にできる。

### 5.1. 通常の公開鍵認証との違い

| 項目 | 公開鍵認証 | 証明書認証 |
| --- | --- | --- |
| 信頼の単位 | 鍵ペアそのもの | CAの署名 |
| サーバー側の登録作業 | `authorized_keys`に公開鍵を1つずつ追加 | CAの公開鍵を1回設定するだけ |
| 有効期限 | なし（手動で無効化するまで有効） | 証明書に埋め込める |
| 権限範囲の制御 | ファイル管理でしか制御できない | `principals`で証明書自体に制限を埋め込める |

### 5.2. 証明書の種類

- **ユーザー証明書**: ユーザーの公開鍵にCAが署名。ユーザーがサーバーへログインする際に使用。
- **ホスト証明書**: サーバー側の公開鍵にCAが署名。クライアントが`known_hosts`未登録の初回接続時でも、CA署名があれば信頼できる（TOFU: Trust On First Useの問題を回避）。

### 5.3. 発行の流れ

CA用の鍵ペアを作成（これ自体は通常の鍵ペア）。

```bash
ssh-keygen -t ed25519 -f ca_key -C "my-ca"
```

ユーザーの公開鍵にCAで署名し、証明書を発行する。

```bash
ssh-keygen -s ca_key -I "user_akasateru" \
  -n akasateru,deploy \
  -V +52w \
  -z 1 \
  id_ed25519.pub
```

| オプション | 意味 |
| --- | --- |
| `-I` | 証明書の識別子（ログに残る） |
| `-n` | principals。証明書が有効なユーザー名/ホスト名のリスト |
| `-V` | 有効期限（例: `+52w`で1年） |
| `-z` | シリアル番号（失効管理に使用） |

署名後、`id_ed25519-cert.pub`が生成される。これを秘密鍵とセットで使うと証明書認証になる。

サーバー側（`sshd_config`）でCAの公開鍵を信頼するよう設定する。

```text
TrustedUserCAKeys /etc/ssh/ca_key.pub
```

### 5.4. メリット

- **鍵配布不要**: サーバー追加のたびに`authorized_keys`を更新しなくてよい。CAの公開鍵を置くだけで済む。
- **有効期限管理**: 証明書に期限を持たせられるため、退職者対応などで個別の鍵無効化が不要（自動失効）。
- **principalsによる制御**: どのユーザー名/ホストで使えるかを証明書自体に埋め込める。
- **失効リスト（KRL）**: `ssh-keygen -k`でシリアル番号ベースの失効リストを作成し、個別無効化も可能。

### 5.5. 実務での使いどころ

社内に多数のサーバーがある環境（踏み台経由の多段SSH、クラウド上での大量インスタンス運用など）で有効。生の`ssh-keygen -s`を手動運用するのは小規模・検証用途向けで、本番ではVault、Teleport、Smallstep（`step-ca`）、Netflix BLESSなどのSSH CA管理基盤と組み合わせて使うのが一般的。
