# 1. インタプリタとコンパイラ

ソースコードを実行可能な形にする2つの方式。

## 1.1. コンパイラ方式

ソースコード全体を事前に機械語（またはバイトコード）に変換してから実行する。

- 実行前に変換（コンパイル）の工程が必要
- 実行時は変換済みの機械語がそのまま動くため高速
- 代表言語: C, C++, Go, Rust, Swift

## 1.2. インタプリタ方式

ソースコードを逐次読みながらその場で解釈・実行する。

- 事前のビルド工程なしにすぐ実行できる
- 1行ずつ解釈するオーバーヘッドがあり、コンパイル方式より実行速度は劣る傾向
- 代表言語: Python, Ruby, PHP（伝統的な実行モデル）

## 1.3. 比較表

| | コンパイラ | インタプリタ |
|---|---|---|
| 実行前の変換 | 全体を機械語に変換 | 変換せずそのまま解釈 |
| 実行速度 | 速い | やや遅い |
| エラー発覚 | コンパイル時にまとめて検出 | 実行してその行に到達するまで気づかない |
| 開発体験 | ビルドが必要、即時実行はできない | 書いてすぐ実行できる |

## 1.4. 実際のハイブリッド方式

現代の主要言語の多くは純粋なインタプリタではなく、以下のようなハイブリッド構成を取る。

- **バイトコード方式**: ソースコードを中間表現（バイトコード）に変換し、仮想マシン（VM）上でインタプリタ実行する（例: Java の JVM、Python の CPython）
- **JITコンパイル**: 実行しながら頻繁に使われる部分を機械語に変換してキャッシュし、以降の実行を高速化する（例: JavaScriptエンジン(V8)、Java の HotSpot VM）

つまり「コンパイラ vs インタプリタ」は言語仕様ではなく実装（処理系）の選択であり、同じ言語でも処理系によって方式が異なることがある。
