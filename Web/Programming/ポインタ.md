# 1. ポインタ

メモリ上のアドレス（値が格納されている場所）を格納する変数。C/C++など低レベル言語で明示的に扱う。

## 1.1. 基本構文（C言語）

```c
int x = 10;
int *p = &x;        // p は x のアドレスを持つ
printf("%d", *p);   // *p でアドレス先の値を取り出す（デリファレンス）→ 10
```

| 記号 | 意味 |
|---|---|
| `&x` | 変数 `x` のアドレスを取得 |
| `*p` | ポインタ `p` が指す先の値を取得（デリファレンス） |
| `int *p` | `p` は「intを指すポインタ」であるという宣言 |

## 1.2. なぜ必要か

値そのものをコピーせず「場所」を渡せるため、以下が可能になる。

- 関数に大きなデータ（配列・構造体）を渡す際、コピーコストをかけずに参照できる
- 関数の中から呼び出し元の変数を直接書き換えられる（参照渡し相当の動作）
- 動的に確保したメモリ（ヒープ）を扱える（`malloc`/`free`など）

## 1.3. 他言語との対応

Java・Python・JavaScriptなどではポインタは言語仕様として表に出てこないが、オブジェクトや配列を扱う変数は内部的に「参照（reference）」としてアドレスに近い仕組みを使っている。ただし以下の点でポインタとは異なる。

- ポインタ演算（アドレスに数値を足し引きする）ができない
- アドレスを直接読み書きできない（メモリ安全性のため言語側が隠蔽している）

## 1.4. 危険性

C/C++でポインタを誤って扱うと典型的なバグの原因になる。

- **ヌルポインタ参照**: 何も指していない（`NULL`）ポインタをデリファレンスしてクラッシュ
- **ダングリングポインタ**: 解放済みメモリを指し続けるポインタにアクセス
- **メモリリーク**: 確保したメモリを解放し忘れる

Rustの所有権システムやガベージコレクション付き言語は、これらの問題をコンパイラ・ランタイムが防ぐ設計になっている。
