# 1. cmux（AIコーディングエージェント並列実行ツール）

「cmux」という名称のOSSプロジェクトは、開発元・アーキテクチャの異なる2つが存在する。どちらも「複数のAIコーディングエージェントを並列に動かす」という目的は共通するが、性質が異なるため混同しないよう整理する。

## 1.1. manaflow-ai/cmux（macOSネイティブターミナル）

- **正体**: [Ghostty](../../Web/Tools/mac.md) ベースのネイティブ macOS ターミナルアプリ（Swift + AppKit 製）。
- **コンセプト**: AIオーケストレーターではなく「プリミティブ」を志向。[Claude Code](Claude%20Code.md)・Codex・OpenCode・[Gemini CLI](Gemini%20CLI.md)・Kiro・Aider など、ターミナルで動く任意のエージェントを並列に並べて手動で監督するための土台という位置づけ。
- **ライセンス**: GPL-3.0-or-later（OSS本体は無料）。
- **開発元**: Manaflow AI。

### 1.1.1. 主な機能

- **通知**: エージェントが注意を要するとペイン枠が青くリング表示、タブも点灯する。
- **サイドバー**: gitブランチ、紐付くPRのステータス/番号、作業ディレクトリ、listeningポート、直近の通知テキストを表示。
- **タブ/スプリット**: 垂直タブに加え縦横スプリットが可能。
- **組み込みブラウザ**: WebKitベースのブラウザペインをターミナルと並べて配置でき、スクリプトAPI経由でDOM操作・クリック・フォーム入力を制御できる。
- **SSH対応**: `cmux ssh user@remote` でリモートマシンをそのままワークスペース化できる。
- **セッション復元**: ウィンドウ/ワークスペース/ペイン構成、作業ディレクトリ、スクロールバック、ブラウザのURL・履歴を自動保存・復元する。
- **CLI/ソケットAPI**: ワークスペースやタブの作成、ペイン分割、キー送信、ブラウザURLオープンなどをスクリプトから制御できる。

### 1.1.2. インストール

```bash
brew tap manaflow-ai/cmux
brew install --cask cmux
```

公式サイトから `.dmg` をダウンロードして Applications にドラッグする方法もある。

### 1.1.3. 主要キーバインド

| キー | 動作 |
|---|---|
| ⌘N | 新規ワークスペース |
| ⌘T | 新規サーフェス |
| ⌘D | 右にスプリット |
| ⌘I | 通知パネル表示 |
| ⌘⇧U | 最新未読へジャンプ |

無料OSSに加え、有料の Founders Edition（優先バグ修正・cmux AIへの早期アクセス等）も提供されている。

## 1.2. coder/cmux（社内名 "Mux" / Coder製）

- **正体**: 並列エージェント開発向けのデスクトップ＆ブラウザアプリケーション。ターミナルマルチプレクサというより統合開発アプリに近い。
- **開発元**: Coder Technologies, Inc.
- **ライセンス**: AGPL-3.0。

### 1.2.1. 主な機能

- **隔離ワークスペース**: ローカル実行、git worktree、SSH経由のリモート実行に対応し、エージェントごとの作業を隔離できる。
- **マルチモデル対応**: Sonnet-4・Opus-4・GPT-5・Grok に加え、Ollama（ローカルLLM）やOpenRouter経由のモデルも利用可能。
- **統合開発機能**: VS Code拡張、コード検査機能、Git差分表示UI、Markdown出力（Mermaid図・LaTeX対応）を備える。

## 1.3. 使い分けの目安

- **manaflow-ai/cmux**: 既存のCLIエージェント（Claude Code等）をターミナル上にたくさん並べ、通知を見ながら手動で監督したい場合に向く。macOS専用。
- **coder/cmux**: git worktreeやリモート実行の隔離、マルチモデル切り替えなど、より統合的なワークフローを求める場合に向く。

いずれも「1つのターミナル/アプリ内で複数エージェントを並列稼働させ、通知ベースで注意が必要な箇所だけ人間が介入する」という設計思想は共通している。並列エージェント運用を検討する際は、既存のツールチェイン（[Claude Code](Claude%20Code.md)中心か、マルチモデルを使い分けたいか）に応じてどちらのアプローチが合うか判断するとよい。
