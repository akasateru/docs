# Codex CLI

OpenAIが提供するターミナル常駐型のAIコーディングエージェント。[Claude Code.md](./Claude%20Code.md) と同じ「CLIで動く自律エージェント」というカテゴリの競合製品。

## 1. アーキテクチャの思想

- **Claude Code**: ローカル完結の対話ループが基本、必要に応じてクラウドに処理を逃がす構成。コード品質・深い推論を重視
- **Codex CLI**: ローカルCLI＋ChatGPT経由のクラウド非同期サンドボックスが強力。速度・効率・オープン性を重視

## 2. ベンチマーク・性能傾向

- コーディングエージェント指標（Terminal-Bench 2.1）ではGPT-5.6 Solが85.8%、Claude Opus 5が84.6%とSolがやや優勢
- 一方SWE-bench Pro（実務寄りタスク）ではClaude Opus 4.7が64.3% vs Codex/GPT系58.6%と、Claude側が約5.7ポイントリード
- 500人超の開発者アンケートでは「日常使いは65%がCodexを好む」一方、「ブラインドでコード品質を評価すると67%がClaude Codeの出力をよりきれいと評価」という逆転現象がある
- Codexは同じタスクでトークン消費が約1/4と、コストパフォーマンスに強み

大まかには「速さ・コスト・自律性ならCodex、コード品質・長文脈での一貫性ならClaude Code」という住み分け（2026年8月時点の評価）。

## 3. コンテキスト・記憶の扱い

- **Codex**: デフォルト256K（GPT-5.4以降は最大1M）。「diffベースの忘却」＋MCP経由の「Memories」サーバでセッションをまたぐ構造化記憶
- **Claude Code**: 1Mトークンの長文脈、auto-memoryで古い文脈を要約しながら保持（diffで捨てるのではなく要約する方式）

## 4. オープンソース化の経緯

2段階でオープンソース化が進んでいる。

- **2025年4月**: Codex CLI自体をApache-2.0でオープンソース化（ローカルで動く軽量コーディングエージェントとして）
- **2026年8月20日**: Codexのコア基盤である「Harness」フレームワーク本体をApache-2.0で完全オープンソース化。`codex exec` CLI、Codex SDK、app-serverの3コンポーネントが含まれ、他社が自由に改変・商用利用してエージェントアプリを作れるようになった

2026年8月時点でGitHub上67,000スター・9,000フォーク・コントリビューター400人規模。CLI自体はRust製で、npm/Homebrewで導入できる。

## 5. モデル面での関係

Codex CLIは名前の由来通りOpenAIのモデル専用（GPT-5.6 Sol/Terra/Lunaなど）。これに対し [Cursor.md](./Cursor.md) はエディタ製品としてOpenAI/Anthropic/Google等のモデルを併用できる点で設計思想が異なる。
