# 1. Herdr（AIコーディングエージェント向けターミナルマルチプレクサ）

Rust製のOSSターミナルマルチプレクサ。tmuxのAIエージェント特化版という位置づけで、[Claude Code](Claude%20Code.md)・Codex・Copilot CLI・Cursor Agent・Devinなど15種類以上のエージェントを1つのターミナル内で並列に管理できる。並列エージェント運用ツールという括りでは[cmux](cmux.md)と同じ枠。

## 1.1. 正体・特徴

- **実装**: Rust製の単一バイナリ（約10MB）。Electron等を使わず軽量。
- **動作モデル**: 今使っている既存のターミナル（iTerm2・Warp・Ghostty等）の中で動く「薄く足す」タイプのツール。cmux（manaflow-ai版）のように専用ターミナルアプリへの乗り換えを必要としない。
- **バックグラウンド常駐**: サーバーとして常駐し、ペイン/ウィンドウを閉じてもエージェントの処理はバックグラウンドで継続する。後から再接続すれば作業が失われていない。
- **状態管理**: CLI・ソケットAPI経由で各エージェントのライフサイクル状態（作業中・入力待ち・完了など）を取得できる。

## 1.2. 状態検出の仕組み（cmuxとの違い）

- **Herdr**: ターミナルの出力スナップショットを既知のマニフェスト（各エージェントの出力パターン定義）と突き合わせて状態を推測する「検出」方式。
- **coder/cmux**: 対応エージェントにセッションフックを仕込み、各エージェントのネイティブresumeコマンドを保存する「教えてもらう」方式。

推測ベースのHerdrは検出ロジックの巧妙さに依存するのに対し、フックベースのcmuxは情報源が明示的な分、構成がより堅牢という評価がある。

## 1.3. Claude Codeしか使わない場合の位置づけ

Claude Codeには元々、[Agent](Claude%20Code.md)ツールに`isolation: "worktree"`オプションがあり、サブエージェントを自動でgit worktree隔離しながら並行実行できる（詳細は [Claude Code.md](Claude%20Code.md) の13節）。

そのため、**Claude Code単体しか使わない場合、Herdr/cmuxが持つ「複数の異なるエージェントツールを横断して1画面で扱う」という強みは活きず、機能面での差はほぼなくなる**。差が出るのは以下のようなケースのみ：

- 1つのサブエージェントタスクではなく、複数の独立したトップレベルセッションを自分で行き来しながら並行運用したい場合（手動なら複数タブ＋都度`git worktree`が必要）
- 3つ以上のエージェントを頻繁に並列稼働させ、状態の一覧性・通知・バックグラウンド永続化が欲しい場合

逆に言えば、並列数が少ない・Claude Codeしか使わないという条件では、アプリ単体で実質同じことができ、無理にツールを導入する必要はない。

## 1.4. 使い分けの目安

- **既存のターミナル環境を変えたくない・軽量に済ませたい** → Herdr
- **専用ターミナルアプリのリッチなUI（通知パネル、組み込みブラウザ等）が欲しい** → [manaflow-ai/cmux](cmux.md)
- **git worktree隔離やマルチモデル切り替えを含む統合開発機能が欲しい** → [coder/cmux](cmux.md)
