## 3. Transformerアーキテクチャの基礎（エンコーダー・デコーダー）

- **エンコーダー**: 入力トークン列を、双方向の文脈を考慮したベクトル表現に変換する
- **デコーダー**: エンコーダーの出力をCross-Attentionで参照しつつ、自身のSelf-Attentionで既生成トークンも参照し、次のトークンを自己回帰的に生成する
- **エンコーダー・デコーダー型**（Transformer原型、T5、BARTなど）: 上記2つを組み合わせる。翻訳・要約などInputとOutputが明確に異なるタスクに強い
- **デコーダーのみ型**（GPT、Claudeなど）: エンコーダーを持たず、入力も出力も同じデコーダー（自己注意のみ）で処理する。現在のLLMの主流

## 4. モデルの公開形態

- **プロプライエタリモデル**: 重み・ソースコード・学習データが非公開で、API経由のみ利用可能（例: Claude、GPT、Gemini）。ベンダーロックインのリスクがある一方、性能・サポート・運用の手軽さで優れることが多い
- **オープンウェイト/オープンソースモデル**: 重みが公開され自前でホスティング・改変可能（例: Llama、Mistral、DeepSeek、Qwen）。自由度は高いが自前でLLMOps基盤を持つ必要がある
- LLMOpsでは「プロプライエタリAPIを使うか、オープンウェイトを自前でホスティングするか」がコスト・レイテンシ・データガバナンス・カスタマイズ性のトレードオフとしてよく議論される

## 5. エージェント型システムの分類

Anthropicの整理では、エージェント型システム（Agentic Systems）は上位概念で、その下に2種類がある。

- **ワークフロー（Workflows）**: LLMとツールが、あらかじめ人間が書いたコードのパスに沿ってオーケストレーションされる。予測可能性・一貫性が高い
- **エージェント（Agents）**: LLM自身が次に何をするか・いつ終わるかを動的に決定する。柔軟だが予測可能性は下がる

実務では、最初からエージェントで作らず「シンプルなAPI呼び出し → ワークフロー → 本当に必要な場合だけエージェント」の順で複雑さを上げるのが推奨される（タスクの複雑さが、精度低下や遅延のコストに見合うかで判断する）。

## 6. 大規模プラットフォーマーのLLM推論コスト対策

Google・Amazon・Microsoft・Metaなど大手は、以下の層でLLM推論コストに対処している。

- **専用シリコンへの投資**: Google TPU、Amazon Trainium/Inferentia、Microsoft Maia、Meta MTIA。Nvidia GPUのマージンを内製化し、電力・冷却も含めた総所有コストを最適化する
- **推論効率化技術**: 量子化、蒸留（大モデル→小モデル）、バッチング、KVキャッシュ最適化/プロンプトキャッシング、Mixture-of-Experts（MoE、一部パラメータのみ活性化）
- **収益モデルでの吸収**: 広告収益での無料枠補填、クラウド事業（AWS Bedrock、Azure OpenAI Serviceなど）の付加価値としての従量課金、既存ユーザー基盤への大規模償却
- 近年は「モデルをどう安くするか」より「電力とデータセンター用地の確保」がボトルネックになりつつある（原子力発電契約の締結など）
- 一般企業のLLMOpsで現実的なコスト最適化レバーは、プロンプトキャッシング・タスクに応じたモデル選択（軽量モデル活用）・バッチAPI活用

## 7. Agentic Commerce

AIエージェントがユーザーに代わって商品の検索・比較・決済までを自律的に行う商取引の形態（5章の「エージェント」の応用領域）。2025年後半〜2026年にかけて、大手決済ネットワークとAI企業が相次いで標準規格を発表し急速に整備が進んでいる。

### 7.1. 主要プロトコル（2026年時点）

| プロトコル | 主体 | 概要 |
|---|---|---|
| **ACP**（Agentic Commerce Protocol） | OpenAI + Stripe | マーチャント・金額を紐づけた単発利用の「Shared Payment Token」を発行し、エージェント経由の決済を安全に実行 |
| **AP2**（Agent Payments Protocol） | Google | 2025年9月発表。Mastercard・PayPal・Coinbase・Amex・Salesforceなど60社以上が参加。Intent/Cart/Paymentの3種の署名付き「Mandate」（W3C Verifiable Credentials）でエージェントの意図・カート内容・支払いを検証可能にする。ステーブルコイン決済もカード・銀行送金と同列に扱う |
| **TAP**（Trusted Agent Protocol） | Visa + Cloudflare | 2025年10月発表。エージェントの身元をHTTPリクエストヘッダーに署名として埋め込み、加盟店がVisaのディレクトリで検証 |
| **Agent Pay** | Mastercard | 2025年4月発表。「Agentic Token」でエージェント経由の取引を認証。AP2にも参加し相互運用 |

### 7.2. Mandateによる支出上限の設計

AP2では、ユーザーがエージェントに「白紙委任」を渡すのではなく、都度スコープを絞った許可を段階的に与える。

- **Intent Mandate（意図の委任）**: 「〇〇というジャンルの商品を探して」「予算は◯円まで」など、事前に許可する範囲を署名付きで定義
- **Cart Mandate（カートの委任）**: エージェントが実際に選んだ商品・金額をユーザー（または事前ルール）が確認・承認
- **Payment Mandate（決済の委任）**: 承認された内容に基づいて初めて決済トークンが発行される

ACPも同様に、特定の店・特定の金額に紐づいた単発利用トークンを発行する設計。これは、Webサイトに仕込まれた指示にエージェントが騙されて勝手に買い物してしまう（プロンプトインジェクション経由の誤発注）などのリスクから利用者を守るためのガードレールとして機能する。

### 7.3. ステーブルコイン

米ドルなど特定の法定通貨と1対1で価値が連動するように設計された暗号資産（例: USDC、USDT）。発行会社が発行量と同額の準備金を保有することで価値を裏付ける方式が主流。通常の暗号資産と異なり価格変動が小さいため決済用途に向く。

銀行の営業時間や最低手数料に縛られず、24時間365日・少額・国境を越えた即時送金が可能な点が、AIエージェント同士が自動で小口決済を繰り返すAgentic Commerceの文脈と相性が良く、AP2が対応を進めている理由。
