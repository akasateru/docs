# パーティデータ戦略

ゼロ・ファースト・セカンド・サードパーティデータの分類と、広告・EC・SaaS領域での活用戦略。サードパーティCookie廃止を背景に、ファーストパーティデータを軸とした戦略設計が重要になっている。

## 1. データの分類

データの取得元・関係性によって4種類に分類される。

- **ゼロパーティデータ**：ユーザーが自ら意図的に企業へ提供するデータ（好み、購入意向、プロフィールなど）。アンケートや診断コンテンツ、会員登録時の嗜好入力で取得。最も精度が高いが、取得コスト（ユーザーに入力してもらう手間）も高い。
- **ファーストパーティデータ**：自社が直接収集する行動・取引データ（サイト閲覧履歴、購買履歴、アプリ利用ログ、CRM情報）。自社が完全にコントロールでき、プライバシー規制下でも比較的安全。現在最も重視されている。
- **セカンドパーティデータ**：他社のファーストパーティデータを提携によって共有してもらうもの。パートナー企業とのデータ連携や共同キャンペーンで利用。
- **サードパーティデータ**：データブローカーなど外部業者が複数ソースから集約・販売するデータ。Cookie規制やiOS ATT等により取得・活用が年々困難化しており、多くの企業が脱却を進めている領域。

## 2. 背景：なぜ今重要か

- **サードパーティCookie廃止**：Chromeも段階的廃止の方向（Privacy Sandbox）。Safari/Firefoxは既にブロック済み。
- **iOS ATT（App Tracking Transparency）**：モバイル広告のコンバージョン計測精度が大幅低下。
- **プライバシー規制強化**：GDPR、CCPA、APPI（日本の個人情報保護法）など。

これにより広告業界は「ターゲティングの燃料」を失いつつあり、その穴を埋める形でEC・SaaSが持つファーストパーティデータの価値が急上昇している。

## 3. 領域別の活用戦略

### 3.1. 広告領域

サードパーティCookieの代替技術・手法：

- **Contextual targeting**：ユーザーではなくコンテンツ文脈でターゲティング（原点回帰）。
- **Cohort-based targeting**（Topics API等）：個人を特定せず興味関心グループ単位で配信。
- **Data Clean Room**：広告主とパブリッシャー/プラットフォームが生データを渡さずにマッチング・計測する仕組み（Google Ads Data Hub, Amazon Marketing Cloud, Snowflake Data Clean Rooms等）。詳細は[4.2](#42-data-clean-room)を参照。
- **リテールメディア**：EC事業者が自社の購買ファーストパーティデータを武器に広告枠を販売（[3.2](#32-ec領域)参照）。

自社が広告主なら「ファーストパーティデータをどう広告プラットフォームに安全に受け渡すか」（Clean Room活用、Conversion API連携）が鍵。自社が媒体/プラットフォームなら「サードパーティに頼らない独自のターゲティング資産」の構築が競争力の源泉になる。

### 3.2. EC領域

ECは購買・閲覧・カート・検索という質の高いファーストパーティデータを大量に持ち、活用は2段階に分かれる。

**Stage 1: 自社CX向上（従来型）**

- レコメンデーション、パーソナライズ配信、CRM/LTV予測、離反防止。
- ゼロパーティデータ（診断コンテンツ、好み入力）と組み合わせて精度を上げる。

**Stage 2: リテールメディア化（トレンド）**

- 楽天、Amazon、Instacart、Yahoo!ショッピングのように、蓄積した購買データを外部ブランド企業への広告商品として販売。
- ブランド側は「実購買に基づくターゲティング」ができ、Cookie依存の広告よりコンバージョン精度が高い。
- ECにとっては本業（物販）より粗利率の高い新規収益源になる。
- ブランド側とデータを共有する際、PII（個人情報）を渡さずに集計レベルでマッチングするClean Room設計が必須（プライバシー法対応）。

### 3.3. SaaS領域

SaaSにおけるparty dataは、マーケティングだけでなく**プロダクト主導の意思決定（Product-Led Growth）**に直結する。

- **プロダクト利用ログ（ファーストパーティ）**：機能利用頻度、オンボーディング完了率、ログイン頻度 → ヘルススコア・チャーン予測・アップセルシグナルに直結。
- **PQL（Product Qualified Leads）**：「無料プランでこの機能を◯回使った」等の利用データを起点にセールスへ引き渡す、ゼロパーティ的な意図表明の代替指標。
- **Reverse ETL / Warehouse-native CDP**：DWH（Snowflake, BigQuery）に溜まったプロダクトデータをCDP経由でSalesforce, HubSpot, 広告プラットフォームへ書き戻す構成が主流化（Hightouch, Census等）。

SaaSはBtoBが多く対象者数が少ない分、EC/広告ほど「データ量で勝負」しづらく、質（利用シグナルの解像度）で勝負する。外部広告ターゲティングへの活用は少ないが、ABM（アカウントベースマーケティング）で自社ファーストパーティデータ + 企業属性データ（セカンド/サードパーティ）を組み合わせるのが定石。

## 4. 横断技術

3領域に共通する基盤技術・概念。

### 4.1. CDP（Customer Data Platform）

ファーストパーティデータを統合する基盤。Segment, Rudderstack, Treasure Data等。3領域共通で必要になる中核インフラ。

### 4.2. Data Clean Room

生データを渡さず集計・マッチングのみ可能にする仕組み。広告主⇄EC/媒体のデータ連携で必須化しつつある。PIIを露出せずに「共通ユーザーへのリーチ」「コンバージョン計測」を行える点が価値。

### 4.3. Identity Resolution

Cookie/デバイス/会員IDをまたいで「同一人物」を名寄せする技術。精度が全戦略の土台となる。

### 4.4. 同意管理（CMP: Consent Management Platform）

ゼロ/ファーストパーティ収集の前提。GDPR/APPI/CCPA対応とセットで設計する必要がある。

### 4.5. Reverse ETL

DWHに溜めたデータを各種SaaS/広告ツールへ書き戻す仕組み。SaaS発の利用データを他領域に活かす橋渡しとなる。

## 5. 戦略の軸（まとめ）

1. **サードパーティ依存の解消**：広告は特に急務。EC/SaaSはファーストパーティ資産の「輸出」でここに応える側になれる。
2. **データを資産から収益に転換**：EC/媒体はリテールメディア化、SaaSはPQL活用による営業効率化で、データ収集コストをペイする設計にする。
3. **プライバシー・ガバナンスが競争力の前提**：Clean Room・同意管理を後付けせず設計段階から組み込む企業が、規制強化局面で勝ち残る。
